# Communication Hub

[English](README.md) | [한국어](README_ko.md)

여러 앱의 소통·업무 요청을 한곳에서 처리하는 로컬 Rust 서비스. **현재 구현된 어댑터는 카카오톡이다. Discord·Slack·Notion은 확장 대상으로만 선언되어 있으며 아직 연결하지 않았다.** Notion은 채팅창과 동일하게 취급하지 않고 문서·댓글 작업 공간으로 구분한다.

**상태: 실험적 알파.** 실제 macOS에서 텍스트 전송을 검증했다. 새 native 자동 파일 업로드의 전체 흐름 검증은 아직 남아 있다. 새 설치에서는 자동화를 꺼둔다.

```mermaid
flowchart LR
    K[카카오톡 어댑터] --> E[공통 이벤트]
    F[향후 앱 어댑터] -.-> E
    E --> Q[SQLite 영속 큐]
    Q --> W[작업 처리와 정책]
    W --> M[로컬 모델 실행기]
    M --> P[답변·승인 자료 계획]
    P --> A[대상 앱 어댑터]
    A --> R[검증·보류·미확인 기록]
```

## 기능

- **앱·계정·대화 ID**로 이벤트와 방별 기록을 분리한다.
- 모델 호출 전에 수신 작업을 저장한다. 모델을 기다리는 동안에도 수신을 이어간다.
- 전송 시도를 기록하고 재시작 중 미확인 작업을 격리한다. 외부 UI를 포함한 정확히 한 번의 전달을 보장하지는 않는다.
- 모델 호출과 외부 발신마다 설정한 Contact-Other 원문을 다시 읽는다.
- 호환되는 로컬 Codex App Server의 Unix 소켓에 WebSocket/JSON-RPC로 연결한다. 모델·추론 강도는 설정 가능하다.
- 같은 사용자 UID의 로컬 제어 소켓으로 상태·어댑터·일시 중지·재개를 관리한다. 중지는 재시작 후에도 유지한다.
- 승인된 JSON + ZIP 묶음을 준비하고 경로·크기·CRC·기본 민감정보 패턴을 검사한다.
- macOS 권한과 접근성 처리는 Swift 헬퍼가 담당한다. 런타임에 Python·가상환경·Orca는 필요하지 않다.

현재 작업 처리기는 하나다. 모든 앱이 이미 동작하는 범용 제품이나 동적 플러그인 로더가 아니라, 어댑터를 확장할 수 있는 초기 기반이다.

## macOS 설치

Rust/Cargo, Xcode Command Line Tools의 `swiftc`, `jq`, 로그인된 카카오톡과 호환되는 로컬 Codex App Server가 필요하다. 사용할 계정에서 지원하는 모델을 지정한다. Rust 시험은 Linux에서도 실행하며 카톡 헬퍼는 macOS 전용이다.

```sh
git clone https://github.com/FMsongX2/communication-hub.git
cd communication-hub
./scripts/setup-macos.sh --model YOUR_SUPPORTED_MODEL_ID
```

설치 스크립트는 Rust 바이너리와 로컬 서명된 헬퍼 앱을 만들고 `~/Library/Application Support/CommunicationHub`에 비공개 설정을 생성한다. 기존 설정은 덮어쓰지 않는다. **서비스 시작·어댑터 활성화·메시지 발신·macOS 권한 허용은 수행하지 않는다.**

1. 생성된 `config.json`과 `contact-other.md`를 검토한다. 실행기 소켓·계정 별칭·지원 모델·실제로 존재하는 승인 프로젝트 작업 위치를 설정한다.
2. 시스템 설정에서 **Kakao Mention Receiver에 전체 디스크 접근**, **Kakao Reply Sender에 접근성**을 허용한다. 코드는 카톡으로 동작을 제한하지만 OS 권한 자체는 더 넓다.
3. `kakao.enabled=true`로 연결한다. 정책·수신 범위를 검토한 다음 `dispatch_enabled`와 `external_auto_send`를 활성화한다. 새 설치에서는 모두 `false`다.
4. 먼저 전면 실행으로 동작을 확인한다.

```sh
"$HOME/Library/Application Support/CommunicationHub/bin/communication-hub" run
```

사용자 LaunchAgent·업데이트·롤백은 [운영 문서](docs/operations.md)를 따른다. 로그인 사용자의 서비스로 실행하며 root 시스템 데몬으로 카톡 UI를 조작하지 않는다. 기존 데스크톱 실행기나 사용자가 시작한 호환 App Server를 연결한다. 인증정보를 추출하거나 실행기 계정을 생성하지 않는다.

## CLI와 호출

```sh
communication-hub status
communication-hub adapters
communication-hub pause
communication-hub resume
```

전체 바이너리 경로로 호출하거나 설치 폴더의 `bin`을 PATH에 추가한다. 카톡 첫 호출은 `@[유이]`, 이전 연결이 있거나 답변 전송이 확인된 방에서는 `@[유이]`와 `[유이]`를 모두 받는다. 태그 없는 메시지는 호출하지 않는다.

전송기는 대상과 호출을 다시 확인하고 동명이거나 모호한 방을 거절한다. 기존 입력 초안을 보관·복원하고 새 발신 말풍선으로 성공을 확인한다. 마우스 포인터는 이동·클릭하지 않는다. 카톡 창을 잠깐 앞으로 가져오고 해당 프로세스에 키를 전달할 수 있다. 잠금·접근성 목록 누락·모호한 대상은 보류한다.

## 로컬 관리보드

비공개 설정에 선택적으로 관리보드를 추가한다.

```json
"dashboard": { "port": 43197, "store_body": false }
```

허브 재시작 후 `communication-hub board --open`으로 인증된 보드를 연다. `communication-hub board`는 토큰 없는 주소를 표시한다. `127.0.0.1`에만 바인딩하고 비공개 API는 재시작 때 갱신하는 인증 토큰을 요구한다. 외부 웹페이지나 미인증 브라우저는 세션·호출 데이터를 읽을 수 없다. 보드는 조회 전용이다.

방 등록부(승인, 유이·유미 스위치, 이름 검증, 맥락 초기화), 수신 heartbeat, 실행기 연결, 호출 태그·처리 결과·접수/최종 receipt를 표시하고 방별 필터·검색·이전 페이지·호출 상세를 제공한다. 호출이 stateless라 보드는 더 이상 실행기 thread를 나열하지 않는다. 실행기 확인은 연결 핸드셰이크뿐이며 thread를 읽거나 재개하거나 시작하지 않는다. **맥락 초기화**를 누르면 그 방의 지난 대화를 유이·유미에게 더는 넘기지 않는다. 대화가 꼬였거나 누군가 이상한 지시를 섞었을 때 새로 시작할 수 있다. 연결 상태와 처리/발신 설정을 구분하며 참여자의 카톡 접속 여부를 의미하지 않는다.

새 호출의 메타데이터는 payload 정리 뒤에도 남긴다. `store_body=true`일 때만 원문도 이 Mac의 비공개 DB에 보관한다. 이전에 삭제된 원문과 태그는 복원하지 않는다. 과거 receipt의 유일한 실제 방 이름으로 연결을 추정할 수 있지만 원문이나 발신자 신원을 만들지는 않는다. 모델 실행 전 차단된 태그 호출도 차단 로그로 남기며, 태그 없는 일반 대화는 호출 기록으로 모으지 않는다. 새 설치에서는 별도 설정 전까지 보드를 꺼둔다.

**방 관리.** 보드에서 오빠가 승인한 방에서만 답한다. 처음 보는 방의 호출은 `room_pending_approval`로 보류하고 방 목록에 승인 대기로 올린다. 방마다 유이·유미를 따로 켜고 끌 수 있다(`sister_disabled_in_room`). “승인 안 된 방도 답하기”를 켜면 예전처럼 모든 방에 답한다. 등록부가 생기기 전에 이미 답하던 방은 업그레이드할 때 승인된 상태로 옮긴다. **이름 검증**은 채팅 목록만 보고 방 이름이 하나뿐인지 확인한 뒤 목록 크기를 기록한다. 목록 크기가 그대로인 동안에는 그 방으로 보낼 때 호출마다 하던 채팅 목록 전체 검사를 건너뛰고, 전체 검사를 다시 하면 기록도 갱신한다. 창 제목·원래 메시지·입력창 확인은 매번 그대로 한다. 이름은 있지만 정확한 태그가 없는 메시지는 `name_without_exact_tag`로 남겨 놓친 호출을 확인할 수 있게 한다.

**데스크톱 앱.** `desktop/`은 같은 보드를 띄우는 작은 Tauri 앱이다. CLI 기본 설정을 통해 허브 비공개 상태에서 보드 주소와 현재 토큰을 읽고, 허브가 재시작해 토큰이 바뀌면 따라가며, 보드가 꺼져 있으면 대기 화면을 보여준다. 로컬 보드 밖으로는 이동하지 않는다. `desktop/`에서 `cargo tauri build --bundles app`으로 빌드하고 로컬 서명 인증서로 서명한다.

## 경계와 제한

- 큰 대화 기록의 접근성 조회는 느릴 수 있다. 현재 알림 조회 간격은 3초다. 보고 있는 방·음소거·미리보기 비활성화·일부 자기발신은 사용 가능한 알림을 만들지 않을 수 있다. 알림이 없으면 호출할 수 없다.
- UI 제목과 표시 내용은 방 ID의 암호학적 검증이 아니다. 목록이나 대상이 모호하면 보류한다. 이름 변경·목록 가상화·다른 언어의 UI는 전송을 막을 수 있다.
- 같은 UID로 실행되는 로컬 프로그램은 제어 클라이언트로 신뢰한다. 파일 권한만으로 사용자 계정 내 악성 프로그램을 격리하지는 않는다.
- 읽기 전용 모델 실행은 일반 쓰기를 막으며 읽기 전체를 격리하는 것은 아니다. 정책 원문과 민감정보 패턴 검사는 완전한 정보 유출 방지 시스템이 아니다.
- 등록된 해당 대화의 승인 자료만 첨부할 수 있다. native 파일 업로드는 실험 상태다. 개인 프로필·정렬 그래프·실제 대화·DB·개인 자료·인증정보는 배포하지 않는다.
- 계정 ID는 설정한 별칭이며 카톡에서 실제 인증된 계정을 자동 판독한 결과가 아니다. 로그인 계정이 바뀌면 범위와 기존 경로를 확인한 뒤 답변을 활성화한다.

## 실행 중 정책 갱신과 Fast 설정

호출은 stateless로 처리한다. 매번 새 일회성 실행기 thread에 현재 Contact-Other와 운영자 지침을 넣어 돌리므로, 외부인이 쓴 내용이 모델 기억에 남지 않고 같은 방 호출끼리 thread를 두고 다투지 않으며 방별 맥락이 길어지지 않는다. 본문 보관(`store_body`)이 켜져 있을 때만 해당 방의 최근 응답 6건(호출 본문과 실제 전송된 답변, 각각 길이 제한·불신 데이터 표시)을 함께 넘긴다. 이전 버전의 방 연결은 보드에 남지만 더 이상 resume하지 않는다. `communication-hub refresh-policy`는 이제 정책 파일만 검사한다.

`intro_text`로 첫 접수 안내의 소개를 설정할 수 있다. 고정 접수 문구는 간결한 한국어 반말을 사용한다. 접수 안내는 모델 생성 전이 아니라 생성과 동시에 돌린다. `kakao.prewarm=true`이면 그 밖의 호출도 아무것도 쓰지 않는 대상 확인을 동시에 돌린다. 전송기의 채팅 목록 전체 검사는 방 이름이 하나뿐임을 확인한다. 이미 열린 방을 찾은 전송은 같은 이벤트·이름·목록 크기로 90초 안에 통과한 검사만 재사용하며, 목록에서 새로 연 방은 늘 다시 검사한다. 모델 카탈로그에서 지원하는 경우에만 `service_tier`를 지정한다(예: Fast의 `"priority"`). 세션과 turn 모두에 전달하며 모델·추론 강도와 별개다. Fast는 사용량이 늘 수 있고 설정 수락이 일정 지연 보장은 아니다.

## 선택적 두 번째 페르소나: Claude로 답하는 유미

`yumi` 설정이 있으면 `@[유미]`·`[유미]` 호출에 유이의 Codex 실행기와 별도로 Claude Code가 답한다. 두 태그가 모두 있는 메시지에는 각자 별도 이벤트로 한 번씩 답한다.

```json
{"yumi":{"claude_bin":"/absolute/path/to/claude","persona":"/absolute/path/to/CLAUDE.md","model":"claude-sonnet-5-5","effort":"low"}}
```

호출은 stateless이고 도구가 없다. 미리 띄운 `claude -p` 프로세스(stream-json 입력) 하나가 메시지 하나에만 답하고 종료하며, 다음 프로세스는 백그라운드에서 띄운다. 그래서 CLI 시작 시간이 답장 경로에 들어가지 않는다. 사용자 설정·훅·MCP·스킬·도구·세션 저장을 모두 끄므로 CLI의 `CLAUDE.md` 자동 로드도 꺼진다. 대신 설정한 페르소나 파일, 화자를 유미로 바꾼 Contact-Other, 호출 규칙이 시스템 프롬프트가 된다. 파일이 필요한 요청은 `[유이]`로 안내한다. 답장 접두사는 `[System-유미] : `이며 이 접두사도 반향으로 거른다. CLI는 소유자 계정으로 로그인돼 있어야 한다. Contact-Other 원문에 유미가 등장하면 화자 교체가 모호해지므로 추정하지 않고 유미 호출을 멈춘다.

## 선택적 표정·미쿠콘 색인

비공개 설정의 `expressions`에 운영자가 보관한 색인을 연결한다.

```json
{"expressions":{"catalog":"/absolute/private/assets/catalog.json","emoticons":null}}
```

항목에는 `id`, `category`, `visual_meaning`, `suitable_situations`, `avoid_context`, `random_eligible`, `format`(`PNG` 또는 `GIF`), `sha256`, `archive`(같은 폴더의 ZIP 파일명), `archive_path`를 넣는다. 전송은 PNG만 한다. 모델이 답한 뒤 코드가 PNG 하나를 균등 랜덤으로 고른다. 같은 이미지 해시는 한 번만 세고 해당 방의 최근 12개 이미지 시도는 뺀다. 모델은 미쿠콘을 보지도 고르지도 않으므로 선택에 토큰·지연이 들지 않는다. 승인된 업무 ZIP을 보내는 답변에는 미쿠콘을 붙이지 않는다.

Rust가 ZIP CRC·PNG 시그니처·크기·SHA-256을 검사하고 원본 이미지를 전송 전에 로컬에 준비한다. 전송기는 텍스트 말풍선과 빈 작성란을 확인한 뒤에만, 같은 실행·같은 검증된 방에서 이미지를 붙인다. 그래서 두 번째 실행이나 두 번째 대상 검사가 없다. 이미지 완료는 검증된 전송 버튼에서 Enter를 누른 뒤 그 방의 업로드 창이 닫히는 것으로 판단한다. 카톡 이미지 말풍선에는 파일명이 없다. 확인되지 않은 이미지는 확인된 텍스트 답변을 불확실로 바꾸지 않으며 영수증과 이력에 남기고 자동 재전송하지 않는다.

선택적 `emoticons`는 `items` 배열에 `{ "text": "…" }`(한 줄짜리 특수문자 표정, 최대 256개)를 담은 비공개 JSON 경로다. 표정도 미쿠콘처럼 코드가 고른다. 답장마다 하나를 균등 랜덤으로 뽑되, 다른 후보가 있으면 그 방 직전 답장의 표정은 뺀다. 모델에는 넣을 표정 하나만 알려주고, 답장에 빠졌으면 끝에 붙인다. 사용 한도 고정 안내에는 붙이지 않는다. 모음이 없으면 표정을 쓰지 말라고 지시한다. 받지 않은 원본 모음을 만들어내지 않는다. 이미지·색인·방별 사용 이력은 저장소에 배포하지 않으며 직접 사용할 자료의 권리를 확인한다.

발신 접두사 `[System-유이] : `는 코드가 한 번 붙인다. 모델은 본문만 작성하며 예전 접두사 포함 출력도 기록·전송 전에 정규화한다. 전송 확인은 UI 관측이며 수신자의 읽음 확인을 뜻하지 않는다.
